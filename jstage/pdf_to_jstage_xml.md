# 論文の PDF を J-STAGE 用の XML にする方法 (調査)

調査日: 2026-09-19 (x280-home)．資料の版は各節に書いた．

## 1. 結論

- **PDF をそのまま XML に変える公式の道具は，いまは無い**．
  J-STAGE の公式ツールは **「全文 XML 作成ツール」(Web．Word の docx か LaTeX を読む)** だけで，
  PDF を読んでいた「書誌 XML 作成ツール」は **2025 年 3 月に全文 XML 作成ツールへ移行した**．
- 手元に PDF しかないときの道は2つ．
  1. **書誌だけ登載する (BIB-J)**: 本文は PDF で公開し，XML には書誌 (題名・著者・所属・
     キーワード・抄録・引用文献など) だけを持たせる．**いちばん軽く，従来の登載と同じ見え方**．
  2. **全文 XML (FULL-J)**: 本文も XML にして全文 HTML で公開する．
     PDF → Word に起こし直す必要があり，**手直しの量が多い** (実例で書誌の約 5 割が手入力)．
- **推奨: まず 1 (書誌のみ)**．全文 HTML が必要になったときだけ 2 を検討する．
  原稿が Markdown や Word で残っているなら，**PDF からではなく原稿から docx を作る**ほうが
  はるかに楽 (4 節)．

## 2. J-STAGE 側の仕組み

| 項目 | 内容 |
|---|---|
| 形式 | JATS 1.1 に基づく J-STAGE 独自の規格 (「J-STAGE XML データフォーマットガイドライン (JATS1.1 版)」) |
| 出力の種類 | **FULL-J** (全文．`<body>` あり) / **BIB-J** (書誌のみ．`<body>` なし) |
| 公式ツール | 全文 XML 作成ツール (Web．編集登載システムの ID が要る) |
| 入力 | **docx** (doc・docm は不可) か **LaTeX** (UTF-8 の tex．画像・bib は zip)．パスワード付きは不可 |
| 一括変換 | docx・LaTeX とも zip にまとめて「一括」で変換できる (論文番号・ページは後で入力) |
| 登載に要るもの | エクスポートした zip + **全文 PDF** + (全文 XML でなければ) **全文テキスト** (検索用) |
| 登載 | 編集登載システムの「一括記事アップロード」へ zip を上げる |

### 2.1 Word のスタイル名で書誌を拾う

全文 XML 作成ツールは **Word の「スタイル」の名前**で書誌事項を見分ける．
**スタイルが付いていない書誌は抽出されず，本文 (`<body>`) に入る**．
既定のスタイル名は次のとおり (変換画面で別名に変えられる)．

| 書誌事項 | 日本語 | 英語 |
|---|---|---|
| タイトル | `TitleJa` | `TitleEn` |
| サブタイトル | `SubtitleJa` | `SubtitleEn` |
| 著者 | `AuthorJa` | `AuthorEn` |
| 所属 | `AffiliationJa` | `AffiliationEn` |
| キーワード | `KeywordJa` | `KeywordEn` |
| 抄録 | `AbstractJa` | `AbstractEn` |
| 謝辞 | `AckJa` | `AckEn` |
| 注釈 | `Notes` | (共通) |
| 引用文献 | `Bib` | (共通) |

JST がスタイル設定済みのテンプレート (`StyleSettingTemplate.docx`・`Sample_ja.docx` など) を配っている．

### 2.2 変換の既知の弱点 (操作マニュアル 第 2.3 版の注意点)

- 変換したものを**そのまま登載はできない**．「XML 検証」「プレビュー」で見て「XML 編集」で直す前提．
- Word の数式は MathML になる (太字と斜体を両方かけると太字だけ残る)．
- 番号付きリスト，本文から図・引用文献へのリンクは崩れることがある．
- **グループ化した図は変換できない**．先に PNG として貼り直す．
- 引用文献の解析 (JATS のタグへの分解) は「なし」にして平文で出すこともできる．

## 3. 手元に PDF しかないときの手順

### 3.1 書誌だけ登載する (JST の案内「全文 XML 作成ツールを利用した PDF ファイルからの書誌事項の登載方法について」第 1.00 版)

準備: **XML 登載で先に巻号を作っておく** (全文 XML 作成ツールでは巻号を増減できない)．
やり方は2通り．

- **A. 書誌だけの Word を作る**
  1. 最終稿の PDF から，書誌事項だけを Word にコピーする (余分な空白を消す)．
  2. 2.1 節のスタイル (`TitleJa` など) を付けて保存する．複数本なら zip に (言語ごとに分ける)．
  3. 全文 XML 作成ツールで巻号を選び「原稿変換」．
  4. 「全文 PDF」に最終稿 PDF をアップロードする．
  5. 「全文テキスト」に PDF の全文をコピー＆ペーストする (検索用．公開はされない)．
  6. 「書誌事項編集」で確認・修正する．
  7. 「エクスポート」で **書誌形式 (BIB-J)** を選んで zip を出し，編集登載にアップロードする．
  8. プレビューで確認して公開．
- **B. 空の Word から作る**
  1. 中身の無い docx (名前だけ付ける) を「原稿変換」する．
  2. PDF をアップロードし，「書誌事項編集」で **PDF の表示から範囲を選んで取り込む** (「PDF 切取」)．
  3. 以降は A の 5〜8 と同じ．

旧ツールとの違い: **テンプレート機能が無い**ので，**1本ずつ**スタイル設定か範囲指定をする．
本数が多いと手間が効く．

### 3.2 全文 XML にする

1. PDF → docx に起こす (Word の「PDF を開く」，Acrobat の書き出しなど)．
2. 2.1 節のスタイルを付け，図 (グループ化を解く)・表・脚注・引用文献を整える．
3. 「原稿変換」→ 検証・プレビュー → XML 編集で直す → FULL-J でエクスポート → 登載．

実例 (Atlas Journal Café，2022-11) では，PDF から起こした Word は構造が複雑になり，
**本文の約 8 割・後付けの約 9 割は自動で変換できたが，書誌の約 5 割は手入力**だった．
図表のキャプション・表の脚注・引用文献や謝辞の見出しは手で直している．
**PDF で制作している雑誌がこの道を取るのは手間も費用も大きい**，という結論．

## 4. 手間を減らす工夫 (自前でできること)

### 4.1 原稿から直接 docx を作る (最も効く)

原稿が Markdown なら，pandoc の `custom-style` でスタイル名を付けたまま docx にできる．
PDF を経由しないので，起こし直しの崩れが出ない．

```markdown
::: {custom-style="TitleJa"}
(論文の題名)
:::

::: {custom-style="AuthorJa"}
(著者名)
:::
```

```
pandoc paper.md -o paper.docx
```

要旨集の要旨 (`build-abstract-pdf` で組んでいる Markdown) にもそのまま使える．

### 4.2 PDF しかないとき: 書誌の docx をスクリプトで作る

3.1 の A を機械化する案．

1. `pdftotext` (または pypdf) で PDF の文字を取り出す．
2. 題名・著者・所属・キーワード・抄録・引用文献の範囲を見分ける
   (体裁がそろった雑誌なら規則で切れる．崩れるものは目で直す)．
3. `python-docx` で段落ごとに `TitleJa` などのスタイルを付けた docx を作り，zip にまとめる．
4. 全文テキストも同じ抽出結果から作る．

未検証．試すなら，まず 2〜3 本で「書誌事項編集」での手直しがどれだけ減るかを測る．

### 4.3 PDF から直接 JATS を作る道具 (参考．J-STAGE にはそのままは使えない)

| 道具 | 出力 | 備考 |
|---|---|---|
| [CERMINE](https://github.com/CeON/CERMINE) | NLM JATS | Java．英語論文向けに学習．日本語の精度は資料に記載なし |
| [GROBID](https://grobid.readthedocs.io/) | TEI XML | JATS へは別に変換が要る．日本語の記載なし |
| [ScienceBeam Parser](https://github.com/elifesciences/sciencebeam-parser) | JATS 系 | eLife 製 |
| pdf2docx (Python) | docx | 横書きの左→右言語向け．日本語の縦書き・混在は対象外 |

全文 XML 作成ツールには **XML の zip を取り込む「インポート」機能**があるので，
これらの出力を J-STAGE の規格に合わせて直せば取り込める理屈にはなる．
ただし**規格の違いを埋める変換 (XSLT など) を自作することになり，日本語論文では割に合わない**見込み．

## 5. 外注

J-STAGE の登載代行・全文 XML 作成は印刷会社などが請け負っている
(例: [日本印刷](https://www.npc-tyo.co.jp/service/j-stage/zenbun-xml/)，
[日本印刷出版](https://jpp.co.jp/j-stage-xml/))．全文 XML を毎号出すなら，費用と
自前の手間を比べる価値がある．

## 6. 決めること (次の一手)

1. 対象は何か (学会誌の論文か，大会の要旨か．本数はどれくらいか)
2. 書誌のみ (BIB-J) で足りるか，全文 HTML (FULL-J) が要るか
3. 元の原稿 (Word・Markdown・LaTeX) が手に入るか (入るなら 4.1 の道)
4. 編集登載システムの ID を誰が持っているか

## 7. 決まったこと とスキル化 (2026-09-19)

6 節への答え: **対象は植生学会誌の論文 (全文 XML)．原稿は無く PDF から作る**．
これに合わせて，スキル **`congress_vs/.claude/skills/pdf-to-jstage-xml/`** を作った (2026-09-19 に **`support-ac/.claude/skills/pdf-to-jstage-xml/`** へ移した)．
使い方は同ディレクトリの `SKILL.md`．

- 方式: 全文 XML 作成ツールで docx から変換するのではなく，**JATS 1.1 の XML を直接組み，
  ツールの「インポート」で読み込んで公式の検証とプレビューを通す**．
  docx を経由すると PDF→Word の崩れを手で直す量が多い (3.2 節) ため．
- 書誌と引用文献は **J-STAGE の記事ページ (日本語版・英語版) の `<meta>`** から取れる．
  英語の題名・氏名・所属・英文要旨・受付日・受理日までそろう．取るのは2ページだけにする．
- 本文・図表は PDF の文字の位置と書体から下書きを作る (植生学会誌の 2014 年の号は InDesign 製で，
  見出し・段落・引用文献の区切りが機械的に取れる)．表は画像を見て組む．
- J-STAGE の DTD 一式 (`https://www.jstage.jst.go.jp/dtds/1.1/`) は公開されていて，手元で検証できる．
- 31(2): 193-218 で最後まで通した: DTD 妥当，J-STAGE の規則のエラー・注意とも 0，
  引用文献 225 件すべてを分解，本文と表から文献へのリンク 409 か所．
- PDF から取るときの落とし穴 (スキルで対処ずみ):
  - em ダッシュが U+0336 で埋め込まれ，PyMuPDF の `dict` 形式では落ちる．
  - 上付きの「2」(m²) の所で行が分かれ，断片の先頭の空白が上付きの高さに置かれる．
  - J-STAGE の登録ずみの引用文献には，ハイフンの脱落などの誤りがある (PDF 版のほうが正確)．
- 未確認: 実際に全文 XML 作成ツールへインポートしての公式の検証 (編集登載の ID が要る)．

## 7.1 雑誌に固有のものを設定へ分けた (2026-09-20)

スキルを他誌へ広げられるように，**植生学会誌にだけ当てはまるものをスキル本体から外した**．

- `journals/<資料コード>.yaml` … 機械が読む設定 (資料コード・ISSN・原稿種別・`eras`・`layout`・
  節の見出しの文言・DOI の形)．今回さらに **`scan`** (旧号のスキャンの柱・透かしの文字と
  図表の題の形) を足し，`extract_scan.py` から雑誌固有の正規表現を無くした
  (NII-ELS が全ページに入れる透かしだけはスクリプト側の既定値)．
- `journals/<資料コード>.md` … 人が読む覚え書き (体裁が変わった巻号とその経緯・
  作った論文の実測・その雑誌で気をつけること)．`SKILL.md` からはこちらへ案内するだけにした．
- `SKILL.md` と `layout.py` の説明からは，巻号を名指しした記述を外した．

**確かめ方**: 分離の前後でスクリプトの出力が変わらないことを，実施ずみの論文で機械的に比べた．
13・14 巻の23本すべてで，`build.py` の XML が**1バイトも変わらない** (md5 が一致)．
`extract_scan.py` も同じ23本で，`body.md`・`report.txt`・`ocr.md`・`floats.txt`・
`pages/`・`figs/`・`tables/` まで旧版と同一だった．

## 8. 図・表の画像に図題 (表題) を入れるか (2026-09-19)

**結論: 入れない**．図番号・図題は XML の `<label>`・`<caption>` に文字で持ち，画像は図の本体だけにする．
表も同じで，表題は `<caption>` に文字で持つ．表はできるだけ `<table>` で組み，画像で載せるときも
画像に表題を入れない．

| 根拠 | 内容 |
|---|---|
| J-STAGE の全文 XML 作成手順書 (JATS1.1 版) の記述例 | `<fig>` の中に `<label>図1</label>`・`<caption>`・`<graphic>` を並べる．図題は `<caption>` の文字．画像の作り方の明文の指示は無い |
| J-STAGE の公式の見本データ (`fullj_51_184`) | 画像 (`Graphics/51_184_1.jpg` など) には「図1」も図題も入っていない (グラフの中の見出しだけ)．表1 は `<table>` で組まれている |
| J-STAGE の公開例 (天理医学紀要 27(2)「全文XML化への取り組み」) | 全文 HTML では，画像のすぐ下に J-STAGE が XML の図番号と図題を文字で表示する (「図2． 国別アクセス数の推移」)．画像には図題が入っていない．表1 は HTML の表で，表題は文字 |
| JATS の Tag Library (NLM) | 図の label と caption は `<fig>` の中に置き，`<graphic>` の中には置かないのがふつう |
| JATS4R の推奨 (Display objects) | 番号は `<label>` に，題は `<caption>` に入れる．表を画像で表すときは `<fig>` ではなく `<table-wrap>` の中の `<graphic>` にする |

画像に図題が入っていると，全文 HTML で図題が二重に出るうえ，図題の文字が検索にも読み上げにも使えない．

スキルでの対応: 図・表の画像は，図題の行を除いた範囲に余白を足し，**図題の手前で切る**ようにした
(植生学会誌 37(1) の図3 で図題の上端が写り込んでいたため)．3本の図表 23 か所すべてで，
切り出した範囲に「図N.」「表N.」が無いことを確かめた．

### 見開きの表 (同日の追記)

植生学会誌 37(1) の表2 は**左右見開きの2ページにわたる横長の表**で，図題も見開きをまたいでいた
(8ページ目の1行目 → 9ページ目の1行目 → 8ページ目の2行目の順)．スキルは，図題の続きの行が
次のページの同じ高さにあることで見開きと判断し，図題を正しい順につなぐ．表の本体は
`table_draft.py --next-clip` で左右の同じ高さの行をつなぐ．42(2) の表1 のように縦に続く表とは区別する．
