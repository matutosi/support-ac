# 論文 PDF から J-STAGE の全文 XML を作る

スクリプトが決まった処理をし，AI は判断の要るところ (照合・表・書誌の確認) だけを受け持つ．
**XML を AI が直接書かない**．AI が直すのは `body.md` と `meta.yaml` だけで，XML は毎回 `build.py` が組む．

## 前提

- Python 3.11 以上と `pip install pymupdf lxml pyyaml` (スクリプトは 3.11 で構文を確かめてある)
- 対象の雑誌の設定 `journals/<資料コード>.yaml` があること (いまは `vegsci.yaml` だけ)．
  その雑誌にだけ当てはまること (体裁の変遷・実測・注意) は `journals/<資料コード>.md` に置く
- 作業ディレクトリは `support-ac/jstage/work/<巻>/<開始ページ>/` にする (git では追跡しない)．
  **開始ページは 3 桁にそろえる** (`13/001/`・`31/193/`．2026-09-24 ユーザ指示．並びが崩れないように)．
  **論文の PDF はその中に `<記事識別子>.pdf` として置く** (外に置かない．`build.py` が既定でここを見る)．
- **記事識別子は J-STAGE の既存のものを使う**．新しい号は `<巻>_<開始ページ>` の形だが，
  2000 年代より前の号は `<巻>_KJ0000…` のような NII 由来の形のことがあり，登載ではそちらが要る．
  `fetch_jstage.py` が記事の URL から `meta.yaml` の `article_id` に書き，`build.py` がそれを使う．
  AI が手で引くときは対応表を使う (`python jstage/article_ids.py get <巻>_<開始ページ>`，逆も可．
  表に無ければ `python jstage/article_ids.py update --vol <巻> [--issn <ISSN>]`)．
- **作業ディレクトリの中に写しや入れ子を作らない** (2026-09-19 ユーザ指示)．J-STAGE が求める
  「資料コード/巻/号/記事識別子/」の入れ子は zip の中の名前にだけ付け，PDF と図表の画像は元のファイルから
  直接 zip へ入れる (`scripts/manifest.py`)．できあがる形:
  ```
  jstage/work/<巻>/<開始ページ>/
    <記事識別子>.pdf          論文の PDF (入力．全文 PDF としてそのまま zip に入る)
    body.md・meta.yaml ほか  下書き (手順 1〜2)
    pages/・figs/・tables/   ページ画像・図表の画像 (手順 1)
    formulas/               別行立ての式の画像 (手順 2．crop.py で切り出す)
    out/<記事識別子>.xml      全文 XML (手順 3)
    out/manifest.json       zip に入れるものの対応表 (手順 3)
    <記事識別子>.zip          登載用の一式 (手順 3)
                            中は <資料コード>/<巻>/<号>/<記事識別子>/ に XML・PDF・Graphics/
  ```

## 実行時のオプション

**独立検証 (手順 5) のやり方**を，スキルを呼ぶときに選べる (2026-09-19 ユーザ指示)．

| 指定 | 日本語で言われたとき | 手順 5 |
|---|---|---|
| `--review none` | 「検証不要」「検証なし」 | 飛ばす |
| `--review opus` | 「opus で検証」「XML の作成と同じモデルで」 | 検証役を `model: opus` で起動する |
| `--review fable` | 「fable で検証」 | 検証役を `model: fable` で起動する |
| `--review sonnet` | 「sonnet で検証」「安く済ませて」 | 検証役を `model: sonnet` で起動する (**既定**) |

- 例: `/pdf-to-jstage-xml jstage/work/<巻>/<開始ページ>/<記事識別子>.pdf --review fable`
- **指定が無いときは `sonnet` で進める (既定．2026-09-19 ユーザ指示)．聞かずに始める**．
  最初の返事で「独立検証は sonnet で行う (既定．`--review` で変えられる)」と一言伝えるだけにし，
  途中の手順 5 で止まって待たない．
  - ただし**表が大きい論文 (目安: セルが 500 を超える，または見開き・縦続きの表がある) のときは，
    手順 1 で表の大きさが分かった時点で1回だけ AskUserQuestion で確かめる**．
    sonnet は小さい字のセル照合で見落としが増えうるため (下の表の欠点)．選択肢は上の4つで，
    手順 5 の表の利点・欠点を添える．「(推奨)」を付けるのは **XML を作ったのと別のモデル**
    (ユーザー設定「書き手と評価者でモデルを変える」)．**`none` には推奨を付けない**．
- 複数の論文を続けて扱うときは，1つの指定をすべての論文に使う．
- 選ばれたやり方は `W/review/triage.md` の冒頭に書く (`none` のときも「独立検証なし (ユーザー指定)」と書く)．
  オプションで指定されたか，既定の `sonnet` か，途中で確かめて決めたかも書く．

## 手順

`S=.claude/skills/pdf-to-jstage-xml/scripts`，作業ディレクトリを `W` とする．

### 0. 書誌と引用文献を用意する (登載ずみの記事のとき)

**J-STAGE の現状の控え (記事ダウンロードの zip) があれば，それから始める** (2026-09-28 ユーザ指示．植生学会誌の 24 巻以降はこちら)．
控えは `jstage/work/_backup/<巻>_<号>/<記事識別子>.zip` (取り方は `jstage/backup.md`)．

```
python $S/from_backup.py jstage/work/_backup/<巻>_<号>/<記事識別子>.zip      # 1本
python $S/from_backup.py jstage/work/_backup/<巻>_<号>/*.zip                 # 号の全部
```

- **ウェブを読まない**．控えの XML に書誌・英文要旨・キーワード・引用文献が，zip に全文 PDF が入っている．
- 作業ディレクトリ `W` は既定で `jstage/work/<巻>/<開始ページ 3 桁>/` (1本のときだけ `--out` で変えられる)．
  `W/<記事識別子>.pdf`・`meta.yaml`・`refs_web.txt` ができる．`meta.yaml` は下の fetch_jstage.py と同じ形で，
  末尾に merge_backup.py と同じ `registered:` の節 (原稿種別・論文番号・カナ・`approved`・`license`) が付く．
  **下の fetch_jstage.py と merge_backup.py は要らない**．
- 既にある `meta.yaml` は上書きしない (`meta.backup.yaml` に書く．`--force` で上書き)．PDF は既にあれば `--force` でも触らない．
  `refs_web.txt` は毎回書き直す．`meta.backup.yaml` に書いたときは `source` が `meta.yaml` に無いので，`apply_backup.py` に `--backup` で控えの zip を渡す．
- 控えに本文 (`<body>`) がある記事は，全文 XML が既に載っているので飛ばす．
- **手順 1 のすぐあとに `apply_backup.py` を流す** (控えの引用文献・要旨を下書きに当てる．手順 1 の「控えから始めたとき」)．
- 控えに無いもの: `article_type` (JATS の記事の種類) と連絡著者は，DTP の号なら手順 1 が PDF から埋める．
  **スキャンの号 (13〜31(1)) では読めない** (帯は白抜きの図柄で OCR に入らない) ので，手順 2 の 9 で AI がページ画像から書く．
  所属の住所も手順 2 の 9 で AI が紙面から書く．受付日・受理日は控えにあれば入る (旧号には無い．スキャンの号は `report.txt` に候補が出る)．

控えが無いときは，J-STAGE の記事ページから取る．

```
python $S/fetch_jstage.py <記事の URL> --out W
```

- 記事ページを**日本語版と英語版で1回ずつ読むだけ**．読んだページは `W/web/` に保存し，2回目からはそれを使う．
  **J-STAGE の AJAX (タブの読み込み) を何度も叩かない** (2026-09-19 ユーザ指示)．
- `meta.yaml` (題名・著者・所属・巻号・日付・DOI・キーワード・英文要旨・著作権) と
  `refs_web.txt` (登録ずみの引用文献) ができる．
- 未登載の記事なら飛ばし，手順 1 のあとで `meta.pdf.yaml` (DTP の号で `extract.py` が書く) をもとに `meta.yaml` を書く．
- 記事ページから取ったあとで控えが手に入ったときは，登録ずみの書誌だけを引き継ぐ (控えから始めたときは要らない)．

  ```
  python $S/merge_backup.py W <控えの zip>
  ```

  `meta.yaml` の末尾に `registered:` の節 (原稿種別・論文番号 `manuscript`・著者名のカナ・最終査読日 `approved`・`license`) を書き，
  `build.py` がそれを XML に出す．何度走らせても節を置き換えるだけ．
  **原稿種別は控えの値を正とする** (2026-09-28 ユーザ確定．`category` より優先)．
  ほかは J-STAGE の「XML データフォーマットガイドライン (JATS1.1 版)」第 2.4 版にしたがい，
  ISSN-L・誌名の略称 (ダウンロード時にシステムが足す)・`custom-meta` (仕様に無い)・`epub-j-stage` (仕様の値は `epub`)・
  著作権表示の先頭の `&copy` (上げ直すときは削除する) は引き継がない．引用文献の正は PDF のまま．

### 1. PDF から下書きを作る

**PDF が2種類ある**が，**どちらを呼んでも自動で切り替わる**ので，いつも次を実行すればよい．

```
python $S/extract.py W/<記事識別子>.pdf --journal <資料コード> --out W
```

| PDF | 見分け方 | 実際に動くもの |
|---|---|---|
| DTP で組んだもの | 書体が複数．図は画像や罫線で入っている | `extract.py` |
| **紙をスキャンして OCR をかけたもの** | 書体が1種類．ページ全体が1枚の画像 | `extract_scan.py` |

- 見分けるのは `scripts/layout.py` の `detect()` で，**PDF そのもの** (書体の数とページ全体を覆う画像) を見る．
  切り替わったときは「紙をスキャンした PDF なので extract_scan.py で処理する」と出る．
  **どの巻号がどちらかは雑誌ごとに違う** (設定の `eras`．経緯は `journals/<資料コード>.md`)．
- `meta.yaml` があれば，**設定 `journals/<資料コード>.yaml` の `eras`** (体裁が変わった巻号の表) と
  引き合わせ，食い違いと，その巻号での引用文献の見出し・原稿種別の文言を `report.txt` に書く．
  新しい体裁の号が出たら `eras` に1行足す (その雑誌での中身は `journals/<資料コード>.md` を見る)．

- `body.md` (本文・謝辞・摘要・引用文献)，`pages/` (ページ画像)，`figs/`・`tables/` (図表の画像)，
  `floats.txt` (表の中の文字)，`report.txt` (自動で判断したこと) ができる．
- `meta.yaml` があれば，ウェブに無い **原稿種別** (総説など) と **連絡著者** (＊と E-mail) を PDF から埋め，
  巻号・受付日などの食い違いを `report.txt` に書く (**DTP の号だけ**．スキャンの号は手順 2 の 9 で AI が書く)．
- **`body.md` が既にあれば上書きせず `body.new.md` に書く** (AI が手で組んだ表などを消さないため)．
  **図表の画像も `figs.new/`・`tables.new/` に書き，`figs/`・`tables/` (手で切り出した画像) には触れない**．
  作り直すときは，AI が手で直したところを `body.new.md` に移してから置き換える．上書きは `--force`
  (このときは `figs/`・`tables/` の画像も消して作り直すので，手で切り出した画像は先に退避する)．
- **図・表の画像には図題 (表題) を入れない**．図題は XML の `<caption>` に文字で持ち，J-STAGE が画像の下に
  表示する (調査は `jstage/pdf_to_jstage_xml.md` の8節)．画像は図題の手前で切り出す．

#### 体裁が変わった巻号

雑誌は何年かごとに組み方を変える．**どの巻号で何が変わったかは設定の `eras`** に書き，
その雑誌での経緯と調べ方は **`journals/<資料コード>.md`** にまとめる
(植生学会誌なら [journals/vegsci.md](journals/vegsci.md)．調べるのは `jstage/pdf_fingerprint.py <巻> <号>`)．

- 決めるのは **PDF そのもの** (`layout.detect`)．設定の表は食い違いに気づくための控え．
- 新しい体裁の号が出たら `eras` に1行足し，覚え書きにも1行書く．

#### 旧号 (スキャン + OCR) のとき

`extract_scan.py` は上と同じもの (`body.md`・`pages/`・`figs/`・`tables/`・`report.txt`) に加えて，
`ocr.md` (ページ・段ごとの行と座標) を書く．次の点が新しい号と違う．

- **OCR の誤りが残る**．和文はおおむね合うが (実測は `journals/<資料コード>.md`)，**欧文の引用文献は崩れる**
  (誌名が `C α nadian／burnal of BotanJ` など)．`report.txt` の「OCR 要確認」を手がかりに，
  **ページ画像を見て直す**のは手順 2 の仕事．
- **斜体の情報が無い** (書体が1種類のため)．学名・誌名の `*斜体*` は**ページ画像を見て付ける**．
- **小型大文字 (small caps) は，ふつうの大文字・小文字に直して書く** (`OLMSTEAD` → `Olmstead`)．
  組み方の違いであって内容の違いではない．本文の引用と引用文献の両方で同じにそろえる．
- **表は OCR がほとんど読めていない**．大きな表 (数十行) は `@image` で画像のまま載せてよい．
- **90 度回した表のページ**は行の高さで見分けて `tables/table_p<ページ>.png` にする．
  これは**ページ全体**なので，表題とノンブルまで入っている．`crop.py` で**表の本体だけに切り直し**，
  **番号どおりの名前にして** (`table3.png`)，`body.md` に枠を AI が手で入れる
  (`python $S/crop.py W --page <ページ> --rect x0,y0,x1,y1 --out tables/table3.png --dpi 200`)．
  PDF は作業ディレクトリの中のものが既定 (2つ以上あるときだけ `--pdf` で渡す)．
  縦組みの表題は画像に入れない (図題・表題は XML の文字で持つ決まり)．
- **図表の枠は当てずっぽうになりやすい**．`report.txt` の「…の枠」の行を見て，
  切り出した画像を**必ず開いて確かめる**．ずれていたら `crop.py` で取り直す．
  - **枠の値は `ocr.md` の座標から起こす**．ページ画像の見た目 (画素) から目分量で決めると，
    表題や表の脚注が 30〜40pt ずれて入ったり欠けたりする．
    画素から換算するときは，`pages/p*.png` は **100dpi (画素 × 0.72 = pt)** (`report.txt` の3行目に書いてある．
    以前は `extract_scan.py` を直に呼ぶと 150dpi になり，換算を取り違えて枠が横に 40〜60pt ずれた．24(1):41)．
  - Windows では，Git Bash の `/tmp/…` のようなパスを PyMuPDF に渡すと開けない．PDF や画像のパスは
    `D:/…` か作業ディレクトリからの相対パスで渡す (24(1):1)．
  - **90 度寝たページ**は，`--rotate 90` で起こした後の「上」が**ページの x が小さい側**．
    表題を外すには `x0` を上げる (下げるのではない)．
  - **2ページ以上に続く表**は，続きのページを**段の一番上から**切る (「（つづき）」の行も入れる)．
    下げて切ると行が黙って落ち，出来上がりを見ても気づけない．
- **図表の拾い方** (2026-09-28 に 24(1) で直した．それでも数え落としと枠のずれは残るので，**図表の数はページ画像で数え直す**)．
  - 図題・表題は「図1」「表1」「Fig. 1」「Table 1」に加えて **「付表1」「Appendix 1」も拾う**．付表は Table 1 と番号が重なるので，
    枠は `:::table TA1 Appendix 1`，画像は `tables/appendix1.png` になる．番号の OCR の崩れ (「Appendix Z.」= 2) も読み替える．
    番号の無い「Appendix.」は拾えない (手で枠を作る)．
  - **同じ番号が後のページにもう一度出たら，ページをまたぐ続き**とみて `fig3_2.png` のような続きの画像にする (枠は作らない)．
    同じページに2つ出たら，2つ目は本文の行の取り違えとみて切り出さない (`report.txt` に出る)．
  - 段落の字下げで始まり，番号のあとに句点の無い行 (「　Figure 1 shows …」「　表1に示す」) は図題にしない．
- **受付日・受理日**は，1 ページ目の脚注の OCR から読んだ候補を `report.txt` に出す (「受付日の候補 …」)．
  月の数字の誤読 (24(1):1 の 8 → 9) は直せないので `meta.yaml` には書かない．**ページ画像で確かめて `history` に書く**．
- J-STAGE に登録ずみの引用文献 (`refs_web.txt`) は，旧号では**件数も並びも本文と合わない**ことがある．
  **正は PDF**．`build_report.txt` の照合は参考にとどめる．
- 和文の中で図表を「Fig. 1」「Table 1」と英語で呼ぶ号がある．`build.py` はこれもリンクする．
- **柱と透かしの文字は雑誌ごとに違う**ので，設定の `scan.junk` に並べる
  (NII-ELS が全ページに入れるものは `extract_scan.py` が既定で外す)．
- **見出しの頭の飾り記号 (■) を OCR が漢字や英字に読む号がある** (24 巻の「欝引用文献」「tw REFERENCES」，綴りの崩れ「REFERIENCES」)．
  引用文献・謝辞・摘要の見出しは，頭の余り3字までと綴りの1〜2字の崩れを許して拾い，`report.txt` に「見出し … を「…」とみた」と出す．
  **本文の小見出しの頭のゴミ (「## 灘はじめに」「## i靉i調査地の概要」) は拾えないので，手順 2 の 1 で AI が外す**．

#### 控えから始めたとき (手順 0 で from_backup.py を使ったとき)

手順 1 のすぐあとに，**控えにあるものを下書きに当てる** (2026-09-28 ユーザ指示「バックアップで使えるものは全て使う」)．

```
python $S/apply_backup.py W
```

控えの zip (既定は `meta.yaml` の `source`) から次を行い，`W/backup_report.txt` に中身を書く．何度走らせてもよい
(引用文献と要旨の節は毎回控えから組み直すので，**AI がそこを直したあとは走らせない**)．

1. **引用文献を控えの `.txt` から組み直す**．`.txt` は J-STAGE が PDF から取った全文で，1件目の行が字下げなし・続きの行が
   全角空白で始まるので，下書きより文献の区切りが確か．ただし**`.txt` の行の並びが崩れている号がある** (24(1):41・53 は
   別の文献の断片が途中に紛れる)．組んだ件数が登録の件数と 3 割以上違えば，`.txt` は使わず下書きの文献を使う．
   下書きの引用文献の節に挟まった偽の見出し (同じページの表の文字．「# 53.78」) は外す．
2. **その文献の OCR の読み誤りを，控えの XML の引用文献で直す**．登録の文献は筆頭著者だけだが，題名・誌名・年・巻・ページの綴りは正しい．
   直すのは読み誤りとはっきり言えるものだけ: 数字もどき (「2DOO」「3斗4」「ll2」→ 登録の数字)・ゴミの字 (「ft〕rest」「Ecologica】Research」)・
   和文の中の英字 (「H本」→「日本」)・英文の語の中の取り違え (c↔e・j↔i・rn↔m・英語に紛れた漢字「Veget乱tion」)．
   **漢字どうし・かなどうしの違いは直さない** (紙面の字のことがある．24(1):65 の「施行事例」は紙面の字で，登録は「施工事例」)．
   直したもの・直さなかったもの (「要確認」)・組にならなかった文献は，すべて `backup_report.txt` に出る．
3. **和文の要旨の節 (摘要・要約) を控えの和文要旨に差し替える** (英文の論文も末尾に和文の「要約」を持つ)．
   控えの要旨は段落が保たれ，OCR の誤りが無い．ただし半角の約物で登録されていることがあるので，和文の中の「,」「.」「()」は全角にする．
   英文の論文の「要約」は，紙面では先頭に題名と著者の行がある (手順 2 で足す)．
   **英文要旨は `meta.yaml` の `abstract.en` が正**．`body.md` に英文の要旨の節 (「# ABSTRACT」) があれば外す
   (`build.py` は要旨の節の中身を和文の要旨として扱うので，残すと英文が和文の要旨に混ざる)．
4. 登録の文献の一覧を `W/refs_backup.md` に書く (手順 2 の 10 の手本)．

題名・著者・所属・キーワード・英文要旨・登録ずみの書誌 (カナ・論文番号など) は手順 0 で `meta.yaml` に入っている．
文献の DOI は手順 3 の `build.py` が `refs_web.txt` から付ける．**控えで使えないのは本文・図表・謝辞** (控えの XML に無い) だけ．

### 2. AI が照合して直す (ここだけがAIによる手作業)

`body.md` を `pages/p*.png` と見比べ，次を順に確かめる．**1つずつ終えてから次へ**．

1. **見出し**: `# ` (大見出し) と `## ` (小見出し) の抜けと段の誤り．
2. **段落の切れ目**: 段やページをまたぐところで，段落が誤ってつながっていないか・切れていないか．
3. **字の抜け**: ダッシュ類 (—) は PDF によって文字情報が無い．`report.txt` の「em ダッシュを補った」も確かめる．
4. **ハイフン**: `report.txt` の「ハイフン除去」を見る．`semi-natural` のような本来のハイフンを消していないか．
5. **斜体・上付き・下付き**: 学名は `*斜体*`，`m^2^`，`CO~2~`．
6. **表**: `:::table` の枠に表を組む．まず下書きを作る．
   ```
   python $S/table_draft.py W/<記事識別子>.pdf <ページ> --clip x0,y0,x1,y1 [--no-merge] [--cols x,x,...] [--key-col K]
   ```
   - `--clip` は `report.txt` の「tableN の枠」をもとに，**見出しの行を除いた範囲**にする．
   - 左端の列を空けた行がある統計表は `--no-merge` (行を前の行につながない)．
   - 「表層/底層」のように1件が2段になる表は `--key-col` (その列の値ごとに1行．2段の短い値は `<break/>`)．
     まばらな列 (最初の行にだけ地点名がある列) を拾えないときは `--cols` で列の始まりを与える．
   - 出力の行をそのまま使い，**見出し (thead・結合セル) と脚注は `tables/tableN.png` を見て AI が手で組む**．
     学名の斜体は `*…*` で出る．
   - **表は2ページ以上続くことがある**．続きの画像が `tables/tableN_2.png` などにでき，`report.txt` に
     「縦に続く」か「見開き (横に続く)」かが出る．必ずページ画像で確かめる．
     - 縦に続く (「表1（つづき）」やキャプションの無い続きのページ): 各ページの下書きの行を下へつなげる．
     - 見開き (左ページに行の見出しと一部の列，右ページに残りの列): `--next-clip` で右ページの範囲を渡すと，
       同じ高さの行を右へつなぐ．図題も見開きをまたぐので，`report.txt` の「図題が見開きで続く」を確かめる．
   - **画像のまま載せる表**: 常在度表のように点線の枠・添字の範囲など XML の表で表せない組み方のものは，
     枠の中に `@image` と1行書く (続きのページの画像も入る)．組まずに `@image` も無いと，画像で代用して
     build_report に出る．
7. **別行立ての式**: 分数・根号・総和など，文字では組めない式は `:::formula` の枠で**画像**にする．
   ```
   python $S/crop.py W --page <ページ> --rect x0,y0,x1,y1 --out formulas/eq1.png
   ```
   - MathML は組まない (「できないこと」の節)．画像は `formulas/eq<番号>.png` に置く
     (`:::formula` の4つ目に名前を書けば別名でもよい．続きは `eq1_2.png`)．
   - **式番号 (1) は画像に入れない**．枠の2つ目に書くと XML の `<label>` になり，J-STAGE が式の横に出す
     (図題・表題を画像に入れないのと同じ)．`--rect` の右端を式番号の手前までにする．
   - 番号の無い式は枠に番号を書かなくてよい (`:::formula E1` だけ)．
   - `CO~2~`・`m^2^`・変数の斜体のような**文字で組める式は画像にしない**．
   - 本文の「式(1)」「式 1」「(1)式」は自動で `<xref>` になる (番号の合う `:::formula` があるときだけ)．
8. **図表の位置**: `:::fig`・`:::table`・`:::formula` の枠は，初めて参照する段落の後ろへ動かす (J-STAGE の指定)．
9. **書誌**: `meta.yaml` を `pages/p001.png` と照合する．英語の氏名の姓・名の分け方，所属の対応．
   - **所属の `ja`・`en` は機関名だけ**にする (`<institution>` は「機関名」．メタデータ項目一覧 82)．
     紙面の所属に住所 (市・郵便番号・国) が組み込まれていれば，`addr:` に分ける．`<addr-line>` になる
     (項番 85．全文 HTML にも書誌の画面にも出ない)．国は `country:` の国コードから表示される．
     ```yaml
     - id: 2
       en: Institute for Basin Ecosystem Studies, Gifu University
       addr:
         en: Gifu 501-11, Japan
       country: JP
     ```
   - **著者の脚注** (「現所属：…」「Present address: …」) は `meta.yaml` に次のように書く．
     `<author-notes>` の `present-address` になる (本文の脚注 `<fn>` とは別物)．
     ```yaml
     author_notes:
     - type: present-address          # <fn fn-type="…">．省くと fn-type なし
       ja: '1 現所属：財団法人国際生態学センター'
       en: '1 Present address: Japanese Center for …'
     ```
     紙面の肩付き番号 (`1`) も文字として入れる (PDF と同じ見た目にするため)．
10. **引用文献**: 1件1行か．`refs_web.txt` があれば件数と中身を比べる
   (**正は PDF**．ウェブ版にはハイフンの脱落などがあることを確かめた)．
   - **控えから始めたときは `backup_report.txt` を上から順に片づける**: 「直した」字はページ画像で合っているかを見る．
     「要確認」はページ画像で決める (紙面の字なら直さない)．「組にならない」「登録にだけある文献」は区切りの誤りか抜けを疑う．
     登録の綴りは `refs_backup.md` にある (筆頭著者だけ．並びと書き方は紙面と違う)．
   - スキャンの旧号の文献は，全角の約物 (「，」「．」「：」) を紙面どおりに直す (欧文の文献は半角)．

- 画像は写さず，`figs/`・`tables/` の元のファイルを zip の中で `{記事識別子}_01.png` からの通し番号に改名して入れる
  (図・画像で載せる表・ページをまたぐ続きの画像を出てくる順に)．
- 古い形の出力 (`W/jstage/` の入れ子) が残っていれば `build_report.txt` に出る．消してよい．
- `refs_web.txt` があれば，引用文献をウェブ版と照合し，中身の違いを `build_report.txt` に書く．
  登録版が項目ごとに組み直された形 (「1) 著者. …」や控えの「著者. 題名. 誌名. (1986) vol.26, p.71-77.」) のときは，
  語で比べて**登録版にだけある語**を出す (登録版は筆頭著者だけなので，紙面にだけある語は数えない)．
  組は著者の頭と年で決め，残りは語の重なりが 4 割以上の相手とだけ組む．組にならない文献は番号を出す．
  残る「違う」は，登録版の足し書き (著者の名・誌名の英訳・副題) か本当の食い違いなので，1 件ずつ紙面で見る．
- 本文の「図1」「Tab. 66」に対応する枠が無いと `build_report.txt` に 1 回だけ出る．**他の論文の図表**なら，
  body.md で `{{-|Tab. 66}}` と書くとリンクしない．
- **ウェブ版の文献にある DOI は，対応する文献に `<pub-id pub-id-type="doi">` で付ける** (ガイドライン 3.1.18．
  J-STAGE の引用文献リンクの反映率が上がる)．記事訂正で全文 XML を上げると文献が置き換わるので，付けないと今ある DOI を失う．
  相手は DOI ごとに年が同じ文献から選ぶ (巻と開始ページの一致，無ければ語の 6 割以上の重なり)．付かなかったものは `build_report.txt` に出る．
  登録版の DOI は「doi:10.…」と接頭辞の無い「10.…」の両方を拾い，年は「(1994)」と「1994;」の両方を読む．
  登録版の年が誤っていても (24(1):19 の Noss 1989 = 紙面 1990)，巻・開始ページが合い語の重なりも 6 割以上なら付ける．
  既に付いている DOI は重ねて付けない．
  紙面に無い文字が文献の末尾に足されるが，今の J-STAGE の画面にも出ている情報なので足す (2026-09-28 ユーザ確定)．
- `build_report.txt` に，リンクできなかった引用・分解できなかった文献・画像で代用した表が出る．
  **引用でない年** (群集名の命名者 `Nozaki et al. 1998` など) が出ることもある．それはそのままでよい．
- 直すのは `body.md` か `meta.yaml`．直したら組み直す．

### 5. 別のエージェントで検証する (独立検証)

XML を作ったエージェントとは**別のエージェント**に，PDF と見比べて検証させる．
**`--review none` のときはこの手順を飛ばし**，`W/review/triage.md` に「独立検証なし (ユーザー指定)」と書いて，
最後の報告で「独立検証はしていない」と明記する．
作った側は自分の直したものを「正しい」と見やすいので，作業に関わっていない目で確かめる．

1. 検証用の資料を作る．
   ```
   python $S/review_pack.py W/out/<記事識別子>.xml --work W --pdf W/<記事識別子>.pdf
   ```
   `W/review/review.md` (XML を読める形にしたもの．リンクの行き先と文献の分解結果つき) と，
   検証用の 200dpi のページ画像 `W/review/pages/` ができる．
2. Agent ツールで検証役を起動する．
   - prompt: `review_prompt.md` の「---」より下の全文．`{作業ディレクトリ}`・`{最終ページ}`・`{記事識別子}`・
     `{論文.pdf}` を埋める．
   - 検証役は**ファイルを書かない** (サブエージェントは報告のファイルを書けない)．結果は返答で受け取る．
   - subagent_type: `general-purpose` (画像を読むため)．
   - **model: 実行時のオプション `--review` で選ばれたモデル (`opus`・`fable`・`sonnet`) にする**
     (上の「実行時のオプション」)．
     指定が無かったときは既定の `sonnet`．ここで改めて聞かない
     (表が大きくて手順 1 で確かめたときは，そこで決まったもの)．
     選ぶときの目安は次の表 (聞くときも，これを添える)．

     | 選択肢 | 利点 | 欠点 |
     |---|---|---|
     | fable | 作った側が opus のとき別のモデルになり，読み違えや思い込みの癖が重なりにくい．ユーザー設定で判断の作業の既定のモデル | 作った側も fable のときは同じモデルになり，文脈の分離だけに頼る |
     | opus | 作った側が fable のとき別のモデルになる．画像の細かい字や表の照合を丁寧に行う | 作った側も opus のときは同じモデルになり，文脈の分離だけに頼る．消費は fable より多くなりうる |
     | sonnet (既定) | 安く速い．作った側が opus・fable のどちらでも別のモデルになる．本文の抜け・引用文献の分解・リンクの行き先のような，文字どうしの突き合わせには足りる | 小さい字の表のセル照合や，斜体・ダッシュ・上付き下付きの判別では見落としが増えうる．表の大きい論文は範囲を分けて渡す |

     - **sonnet の実測 (2026-09-21 時点，15 巻まで 52 本．その後 24(1) まで既定として使った．くわしくは `journals/vegsci.md`)**: 学名の綴り・表の行の脱落・
       引用文献の語の取り違えといった**中身の誤りを実際に見つけている** (綴りの誤り，
       ページをまたぐ表で2行落ちていた，引用文献の「景観」と「景域」の取り違えなど)．
       いっぽう，検証用資料 `review.md` の出し方に引きずられた誤検出もあった
       (番号つきの箇条書きが番号なしに見えた．`review_pack.py` を直して解消)．
     - 量の目安 (実測): 11 ページ・21 地点 × 37 種の表を全セル照合させて，約 19 万トークン・
       ツール 70 回・約 10 分 (fable)．量はモデルよりも確かめる範囲 (表の大きさ・文献の数) で決まる．
     - どちらを選んでも，検証役は別のエージェントなので**文脈は分かれている** (作る途中の資料を見ない)．
       モデルを変えるのは，それに加えて癖の重なりを減らすため．
     - 選ばれたモデルと，オプションで指定されたか最初に聞いて決めたかを `review/triage.md` の冒頭に書く．
   - 検証役には `body.md`・`meta.yaml`・`report.txt` などを見せない (`review_prompt.md` で禁じてある)．
   - 論文が長いとき (目安 20 ページ超) は，範囲を分けて2〜3体に分担させてよい
     (同時に起動する数はユーザー設定の上限まで)．1体の中では順に確かめさせる．
3. 返ってきた結果を，作った側が1件ずつ判断する．
   - 採るもの: `body.md` か `meta.yaml` を直し，手順 3・4 をやり直す．
   - 採らないもの: 理由を書く (原文の誤りをそのまま写している，など．J-STAGE は PDF と HTML の内容が
     同一であることを求めるので，原文の誤りは直さない)．
   - 判断の記録を `W/review/triage.md` に残す (検証役の指摘の要約・採否・理由・直したところ)．
   - 採否は事実で決める．指摘の文字が本当に PDF と違うかは，PDF の文字情報 (`page.search_for`) と
     ウェブ版 (`refs_web.txt`) で確かめる (見た目の空白やダッシュの字形の指摘が，
     PDF の文字情報どおりで採らなかった例がある)．
4. A (内容の誤り・抜け) を直したときは，直したところだけをもう一度検証役に確かめさせる．

## body.md の書式

| 書き方 | 意味 |
|---|---|
| `# 見出し` / `## 見出し` / `### 見出し` | 節 (`<sec>`) の入れ子 |
| 空行で区切った1行 | 段落 (`<p>`) |
| 空行なしで続く2行以上の `- ` / `1. ` | 箇条書き (`<list>`) |
| `*斜体*` `**太字**` `^上付き^` `~下付き~` | `<italic>` `<bold>` `<sup>` `<sub>` |
| `***太字の斜体***` | `<bold><italic>` |
| `__下線__` | `<underline>` (斜体と重ねるときは `__*d*__`) |
| `\*` | 印にしない「*」(表の脚注の「\*1: …」など) |
| `http(s)://...` | `<ext-link>` |
| `# 摘要` (設定の `sections.abstract`) | 和文の抄録 `<abstract>` (段落を保つ．本文からは外す) |
| `# 謝辞` / `# 引用文献` | `<ack>` / `<ref-list>` (引用文献は1件1行) |
| 引用文献の節の `（…）` で始まり年の無い行 | 文献にせず，一覧の末尾の注記 (入れ子の `<ref-list>` の `<p>`) |
| `<!-- ... -->` の行 | 読み飛ばす (メモ) |

図と表の枠:

```
:::fig F1 図1 fig1.png
畦畔の構造と名称．
:::

:::table T1 表1
表の題 (1行目)
<table> ... </table>       ← HTML (thead/tbody/tr/th/td，rowspan/colspan 可) か | 区切りの表
注の行 (表の後ろの行は table-wrap-foot)
:::

:::formula E1 (1)          ← 別行立ての式 (画像は formulas/eq1.png．番号は省ける)
:::
```

- 本文の「図1」「表1」「式(1)」は自動で `<xref>` になる．「著者 年」の引用も自動 (著者表記のかたまりが
  文献の著者名の先頭と一致し，年が同じもの)．「1991a, b」「2004, 2005」のような続きも扱う．
- 表のセルの中の引用もリンクする．**見出しの中の「図1」「表1」もリンクする** (引用はしない)．
- 本文の「Appendix 1」「Appendices 1」「付録1」は，番号の合う `:::table` があれば自動で `<xref>` になる．
  枠の番号は何でもよく (`:::table TA1 Appendix 1`)，枠に書いた呼び名で引く．
- 番号の無い枠 (`:::table T5 付表`・`:::table T3 Appendix`) は，本文の「付表」「in Appendix」をその呼び名で引く (「付表に示した」「（付表）」．24(1):41)．
- HTML の表のセルの `<` は `&lt;` と書く (「&lt;0.01」．そのまま出力される)．
  「図6-1」のような枝番は範囲と取り違えず，「図6」だけをリンクする．
- 原文の表記揺れで自動では当たらない引用は，`{{著者名の先頭 年|表示の文字}}` と書くとその文献へリンクする
  (例: `{{北海道環境科学研究センター 2005|北海道環境科学センター（2005）}}`)．**表示の文字は原文のまま**にする
  (J-STAGE は PDF と HTML の内容が同一であることを求めている)．
- **他の論文の図表を指す「Table 2」「表1」** (「Relevé No. 29 in Table 2 (Suganuma 1983)」) は，
  そのままではこの論文の表へ自動でリンクされる．`{{-|Table 2}}` と書くとリンクしない (表示は原文のまま．21(1):1)．
  引用・図表・式のどのリンクにもかからない．
- **同じ著者の同じ年の文献が2件ある**ときは著者名と年では引けないので，`{{B20|村上 1985}}` のように
  **文献の番号** (`build_report.txt`・`review.md` に出る `B20`) で書く．

## 他の雑誌に広げるとき

**スキル本体 (SKILL.md・scripts/) は雑誌によらない**．新しい雑誌を足すのは次の5歩．

### 1. 資料コードと ISSN を調べる

記事の URL `https://www.jstage.jst.go.jp/article/<資料コード>/<巻>/<号>/<記事識別子>/…` の
`<資料コード>`と，記事ページの ISSN (冊子・電子) を控える．電子 ISSN は `jstage/` の道具の `--issn` に使う．

### 2. 設定を写す

```
cp journals/_template.yaml journals/<資料コード>.yaml
cp journals/_template.md   journals/<資料コード>.md
```

`_template.yaml` の註に，どの値が**必須**で，どれが**自動で決まる**か，どれが**いまは使わない控え**かを書いてある．

| 設定 | 要否 | 何を書くか・どう調べるか |
|---|---|---|
| `journal_id`・`issn`・`title`・`publisher`・`copyright_holder` | **必須** | 記事ページと奥付から |
| `article_types` | **必須** | 1ページ目の帯や目次の言い方 → J-STAGE の article-type．**号による揺れもすべて並べる** |
| `sections` | **必須** | 摘要・謝辞・引用文献の見出しの文言 (和英・号による揺れを並びで)．`build.py` が使うのはこの3つ．`appendix` は `apply_backup.py`・`extract_scan.py` が節の区切りに使う |
| `layout` | **要調整** | 見出しの書体と記号・字下げ・図表の題の形．**字の大きさと柱・脚注の位置は PDF ごとに自動**なので，ここの値は自動で決められなかったときの既定値 |
| `eras` | 任意 | 体裁が変わった巻号 (`jstage/pdf_fingerprint.py <巻> <号> --issn <ISSN>` を二分探索)．無くても動く |
| `scan` | スキャンの旧号があるときだけ | 柱・透かしのうち雑誌固有の文字と，図表の題の形 (OCR 用に緩く) |
| `reference_style`・`doi_template` | 控え | **いまのスクリプトは読まない** |

### 3. PDF が DTP かスキャンかを確かめる

1本で `extract.py` を走らせると自動で振り分ける (`layout.detect`)．
スキャンなら `scan.junk` に柱・透かしの文字を足す (`report.txt` の「透かし・柱として外した」の行を見て，
外し漏れ・外しすぎを直す)．

### 4. 1本で最後まで通し，値を合わせる

`report.txt` の「組み方 (自動)」と `body.md` を見て，`layout` の見出し・字下げ・図表の題を直す．
うまく出ないときに見るところ:

- 見出しが拾えない → `heading_font`・`heading1_prefix`・`heading1_size`・`heading2_size`
- 段落が続いてしまう / 切れすぎる → `indent_min`
- 引用文献が1件にまとまらない → `ref_indent_max`・`ref_size`
- 図表の題を拾わない → `caption_pattern` (スキャンは `scan.caption_pattern`)
- 学名が斜体にならない → `italic_font`

`build.py` → `validate.py` で **DTD 妥当・エラー 0** まで通ったら設定は使える．

### 5. 覚え書きを書く

**その雑誌にだけ当てはまることは `journals/<資料コード>.md`** に書く (体裁の変遷・実測・注意)．
SKILL.md には雑誌固有のことを書かない．

### 合わないかもしれないところ (先に見ておく)

- **引用が番号式 (1) や上付き番号) の雑誌**は，`build.py` の `link_citations` に別の規則が要る (未実装)．
  「著者 年」式なら，姓の書き方 (和英・「ら」「et al.」) は今のままで扱える．
- **図表の題が本文と同じ書体・大きさ**の雑誌は，`heading_font` では拾えない (`caption_pattern` に頼る)．
- **3段組み・横書きでない紙面**は試していない．
- 記事識別子の対応表が要るとき: `python jstage/article_ids.py update --vol <巻> --issn <電子 ISSN>`．

## できないこと (いまの版)

- **数式は画像で載せる (`:::formula` → `<disp-formula><graphic/>`)．MathML は組まない**
  (2026-09-19 ユーザ指示で画像の道を選んだ)．画像なので検索・読み上げには乗らない．
  MathML が要るときは，全文 XML 作成ツールの画面で足すほうが早い．
- 電子付録・Graphical Abstract・ファンド情報は組まない．
- 本文の脚注 (`<fn>`) は扱わない．**紙面に脚注があるときは，参照している段落の直後に
  独立した段落として本文に入れる** (内容を落とさないため．15(2):147 でそうした)．
