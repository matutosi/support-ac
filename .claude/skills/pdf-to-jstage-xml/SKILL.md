# 論文 PDF から J-STAGE の全文 XML を作る

スクリプトが決まった処理をし，AI は判断の要る所 (照合・表・書誌の確認) だけを受け持つ．
**XML を AI が直接書かない**．AI が直すのは `body.md` と `meta.yaml` だけで，XML は毎回 `build.py` が組む．

## 前提

- Python 3.11 以上と `pip install pymupdf lxml pyyaml` (スクリプトは 3.11 で構文を確かめてある)
- 対象の雑誌の設定 `journals/<資料コード>.yaml` があること (いまは `vegsci.yaml` だけ)
- 作業ディレクトリは `support-ac/jstage/work/<巻>_<開始ページ>/` にする (git では追跡しない)．
  **論文の PDF はその中に `<巻>_<開始ページ>.pdf` として置く** (外に置かない．`build.py` が既定でここを見る)．
- **作業ディレクトリの中に写しや入れ子を作らない** (2026-09-19 ユーザ指示)．J-STAGE が求める
  「資料コード/巻/号/記事識別子/」の入れ子は zip の中の名前にだけ付け，PDF と図表の画像は元のファイルから
  直接 zip へ入れる (`scripts/manifest.py`)．できあがる形:
  ```
  jstage/work/31_193/        (巻 31・開始ページ 193 の論文の例)
    31_193.pdf              論文の PDF (入力．全文 PDF としてそのまま zip に入る)
    body.md・meta.yaml ほか  下書き (手順 1〜2)
    pages/・figs/・tables/   ページ画像・図表の画像 (手順 1)
    formulas/               別行立ての式の画像 (手順 2．crop.py で切り出す)
    out/31_193.xml          全文 XML (手順 3)
    out/manifest.json       zip に入れるものの対応表 (手順 3)
    31_193.zip              登載用の一式 (手順 3．中は vegsci/31/2/31_193/ に XML・PDF・Graphics/)
                            (vegsci=資料コード，31=巻，2=号，31_193=記事識別子)
  ```

## 実行時のオプション

**独立検証 (手順 5) のやり方**を，スキルを呼ぶときに選べる (2026-09-19 ユーザ指示)．

| 指定 | 日本語で言われたとき | 手順 5 |
|---|---|---|
| `--review none` | 「検証不要」「検証なし」 | 飛ばす |
| `--review opus` | 「opus で検証」「XML の作成と同じモデルで」 | 検証役を `model: opus` で起動する |
| `--review fable` | 「fable で検証」 | 検証役を `model: fable` で起動する |
| `--review sonnet` | 「sonnet で検証」「安く済ませて」 | 検証役を `model: sonnet` で起動する (**既定**) |

- 例: `/pdf-to-jstage-xml jstage/work/31_193/31_193.pdf --review fable`
- **指定が無いときは `sonnet` で進める (既定．2026-09-19 ユーザ指示)．聞かずに始める**．
  最初の返事で「独立検証は sonnet で行う (既定．`--review` で変えられる)」と一言伝えるだけにし，
  途中の手順 5 で止まって待たない．
  - ただし**表が大きい論文 (目安: セルが 500 を超える，または見開き・縦続きの表がある) のときは，
    手順 1 で表の大きさが分かった時点で1回だけ AskUserQuestion で確かめる**．
    sonnet は小さい字のセル照合で見落としが増えうるため (下の表の欠点)．選択肢は上の4つで，
    手順 5 の表の利点・欠点を添える．「(推奨)」を付けるのは **XML を作ったのと別のモデル**
    (ユーザー設定「書き手と評価者でモデルを変える」)．**`none` には推奨を付けない**．
- 複数の論文を続けて扱うときは，1つの指定をすべての論文に使う．
- 選ばれたやり方は `W/review/triage.md` の冒頭に書く (`none` のときも「独立検証なし (ユーザー指定)」と書く)．
  オプションで指定されたか，既定の `sonnet` か，途中で確かめて決めたかも書く．

## 手順

`S=.claude/skills/pdf-to-jstage-xml/scripts`，作業ディレクトリを `W` とする．

### 0. 書誌と引用文献を J-STAGE から取る (登載ずみの記事のとき)

```
python $S/fetch_jstage.py <記事の URL> --out W
```

- 記事ページを**日本語版と英語版で1回ずつ読むだけ**．読んだページは `W/web/` に保存し，2回目からはそれを使う．
  **J-STAGE の AJAX (タブの読み込み) を何度も叩かない** (2026-09-19 ユーザ指示)．
- `meta.yaml` (題名・著者・所属・巻号・日付・DOI・キーワード・英文要旨・著作権) と
  `refs_web.txt` (登録ずみの引用文献) ができる．
- 未登載の記事なら飛ばし，手順 1 のあとで `meta.pdf.yaml` をもとに `meta.yaml` を書く．

### 1. PDF から下書きを作る

```
python $S/extract.py W/<記事識別子>.pdf --journal vegsci --out W
```

- `body.md` (本文・謝辞・摘要・引用文献)，`pages/` (ページ画像)，`figs/`・`tables/` (図表の画像)，
  `floats.txt` (表の中の文字)，`report.txt` (自動で判断したこと) ができる．
- `meta.yaml` があれば，ウェブに無い **原稿種別** (総説など) と **連絡著者** (＊と E-mail) を PDF から埋め，
  巻号・受付日などの食い違いを `report.txt` に書く．
- **`body.md` が既にあれば上書きせず `body.new.md` に書く** (手で組んだ表などを消さないため)．
  作り直すときは，手で直した所を `body.new.md` に移してから置き換える．上書きは `--force`．
- **図・表の画像には図題 (表題) を入れない**．図題は XML の `<caption>` に文字で持ち，J-STAGE が画像の下に
  表示する (調査は `jstage/pdf_to_jstage_xml.md` の8節)．画像は図題の手前で切り出す．

### 2. AI が照合して直す (ここだけが手作業)

`body.md` を `pages/p*.png` と見比べ，次を順に確かめる．**1つずつ終えてから次へ**．

1. **見出し**: `# ` (大見出し) と `## ` (小見出し) の抜けと段の誤り．
2. **段落の切れ目**: 段やページをまたぐ所で，段落が誤ってつながっていないか・切れていないか．
3. **字の抜け**: ダッシュ類 (—) は PDF によって文字情報が無い．`report.txt` の「em ダッシュを補った」も確かめる．
4. **ハイフン**: `report.txt` の「ハイフン除去」を見る．`semi-natural` のような本来のハイフンを消していないか．
5. **斜体・上付き・下付き**: 学名は `*斜体*`，`m^2^`，`CO~2~`．
6. **表**: `:::table` の枠に表を組む．まず下書きを作る．
   ```
   python $S/table_draft.py W/<記事識別子>.pdf <ページ> --clip x0,y0,x1,y1 [--no-merge] [--cols x,x,...] [--key-col K]
   ```
   - `--clip` は `report.txt` の「tableN の枠」をもとに，**見出しの行を除いた範囲**にする．
   - 左端の列を空けた行がある統計表は `--no-merge` (行を前の行につながない)．
   - 「表層/底層」のように1件が2段になる表は `--key-col` (その列の値ごとに1行．2段の短い値は `<break/>`)．
     まばらな列 (最初の行にだけ地点名がある列) を拾えないときは `--cols` で列の始まりを与える．
   - 出力の行をそのまま使い，**見出し (thead・結合セル) と脚注は `tables/tableN.png` を見て手で組む**．
     学名の斜体は `*…*` で出る．
   - **表は2ページ以上続くことがある**．続きの画像が `tables/tableN_2.png` などにでき，`report.txt` に
     「縦に続く」か「見開き (横に続く)」かが出る．必ずページ画像で確かめる．
     - 縦に続く (「表1（つづき）」やキャプションの無い続きのページ): 各ページの下書きの行を下へつなげる．
     - 見開き (左ページに行の見出しと一部の列，右ページに残りの列): `--next-clip` で右ページの範囲を渡すと，
       同じ高さの行を右へつなぐ．図題も見開きをまたぐので，`report.txt` の「図題が見開きで続く」を確かめる．
   - **画像のまま載せる表**: 常在度表のように点線の枠・添字の範囲など XML の表で表せない組み方のものは，
     枠の中に `@image` と1行書く (続きのページの画像も入る)．組まずに `@image` も無いと，画像で代用して
     build_report に出る．
7. **別行立ての式**: 分数・根号・総和など，文字では組めない式は `:::formula` の枠で**画像**にする．
   ```
   python $S/crop.py W --page <ページ> --rect x0,y0,x1,y1 --out formulas/eq1.png
   ```
   - MathML は組まない (「できないこと」の節)．画像は `formulas/eq<番号>.png` に置く
     (`:::formula` の4つ目に名前を書けば別名でもよい．続きは `eq1_2.png`)．
   - **式番号 (1) は画像に入れない**．枠の2つ目に書くと XML の `<label>` になり，J-STAGE が式の横に出す
     (図題・表題を画像に入れないのと同じ)．`--rect` の右端を式番号の手前までにする．
   - 番号の無い式は枠に番号を書かなくてよい (`:::formula E1` だけ)．
   - `CO~2~`・`m^2^`・変数の斜体のような**文字で組める式は画像にしない**．
   - 本文の「式(1)」「式 1」「(1)式」は自動で `<xref>` になる (番号の合う `:::formula` があるときだけ)．
8. **図表の位置**: `:::fig`・`:::table`・`:::formula` の枠は，初めて参照する段落の後ろへ動かす (J-STAGE の指定)．
9. **書誌**: `meta.yaml` を `pages/p001.png` と照合する．英語の氏名の姓・名の分け方，所属の対応．
10. **引用文献**: 1件1行か．`refs_web.txt` があれば件数と中身を比べる
   (植生学会誌 31(2) では PDF 版が正確で，ウェブ版にはハイフンの脱落などがあった)．

### 3. XML に組む

```
python $S/build.py W
```

- `W/out/<記事識別子>.xml` と対応表 `W/out/manifest.json` を書き，`W/<記事識別子>.zip` にまとめる．
  zip の中は `<資料コード>/<巻>/<号>/<記事識別子>/` に XML・PDF・`Graphics/`．
- 全文 PDF は `W/<記事識別子>.pdf` を使う (別の場所なら `--pdf` で渡せるが，中に置く決まり)．写しは作らない．
- 画像は写さず，`figs/`・`tables/` の元のファイルを zip の中で `{記事識別子}_01.png` からの通し番号に改名して入れる
  (図・画像で載せる表・ページをまたぐ続きの画像を出てくる順に)．
- 古い形の出力 (`W/jstage/` の入れ子) が残っていれば `build_report.txt` に出る．消してよい．
- `refs_web.txt` があれば，引用文献をウェブ版と照合し，中身の違いを `build_report.txt` に書く．
- `build_report.txt` に，リンクできなかった引用・分解できなかった文献・画像で代用した表が出る．
  **引用でない年** (群集名の命名者 `Nozaki et al. 1998` など) が出ることもある．それはそのままでよい．
- 直すのは `body.md` か `meta.yaml`．直したら組み直す．

### 4. 検証する

```
python $S/validate.py W/out/31_193.xml
```

- DTD (J-STAGE の JATS 1.1) と，DTD で分からない J-STAGE の規則 (必須項目・文字数・ID の参照・画像の有無・
  日英そろいの著作権・参照されていない文献や図表) を見る．
  zip の中に XML・PDF・画像がそろっているかも見る (登載するのは zip なので)．DTD 一式は初回だけ取得して `dtd/` に置く．
- **エラー 0 を目標にする**．「注意」の「参照されていない文献」は，表の中でだけ引かれている文献が
  表を画像で代用しているときに出る．表を組めば消える．

### 5. 別のエージェントで検証する (独立検証)

XML を作ったエージェントとは**別のエージェント**に，PDF と見比べて検証させる．
**`--review none` のときはこの手順を飛ばし**，`W/review/triage.md` に「独立検証なし (ユーザー指定)」と書いて，
最後の報告で「独立検証はしていない」と明記する．
作った側は自分の直したものを「正しい」と見やすいので，作業に関わっていない目で確かめる．

1. 検証用の資料を作る．
   ```
   python $S/review_pack.py W/out/<記事識別子>.xml --work W --pdf W/<記事識別子>.pdf
   ```
   `W/review/review.md` (XML を読める形にしたもの．リンクの行き先と文献の分解結果つき) と，
   検証用の 200dpi のページ画像 `W/review/pages/` ができる．
2. Agent ツールで検証役を起動する．
   - prompt: `review_prompt.md` の「---」より下の全文．`{作業ディレクトリ}`・`{最終ページ}`・`{記事識別子}`・
     `{論文.pdf}` を埋める．
   - 検証役は**ファイルを書かない** (サブエージェントは報告のファイルを書けない)．結果は返答で受け取る．
   - subagent_type: `general-purpose` (画像を読むため)．
   - **model: 実行時のオプション `--review` で選ばれたモデル (`opus`・`fable`・`sonnet`) にする**
     (上の「実行時のオプション」)．
     指定が無かったときは既定の `sonnet`．ここで改めて聞かない
     (表が大きくて手順 1 で確かめたときは，そこで決まったもの)．
     選ぶときの目安は次の表 (聞くときも，これを添える)．

     | 選択肢 | 利点 | 欠点 |
     |---|---|---|
     | fable | 作った側が opus のとき別のモデルになり，読み違えや思い込みの癖が重なりにくい．ユーザー設定で判断の作業の既定のモデル | 作った側も fable のときは同じモデルになり，文脈の分離だけに頼る |
     | opus | 作った側が fable のとき別のモデルになる．画像の細かい字や表の照合を丁寧に行う | 作った側も opus のときは同じモデルになり，文脈の分離だけに頼る．消費は fable より多くなりうる |
     | sonnet (既定) | 安く速い．作った側が opus・fable のどちらでも別のモデルになる．本文の抜け・引用文献の分解・リンクの行き先のような，文字どうしの突き合わせには足りる | **未実測** (2026-09-19 時点で比べていない)．小さい字の表のセル照合や，斜体・ダッシュ・上付き下付きの判別で見落としが増えうる．見落としは誰も気づかないまま残るので，表の大きい論文には勧めない |

     - 量の目安 (実測): 37(1) (11 ページ，表2 は 21 地点 × 37 種を全セル照合) を fable で検証して
       約 19 万トークン・ツール 70 回・約 10 分．量はモデルよりも確かめる範囲 (表の大きさ・文献の数) で決まる．
     - どちらを選んでも，検証役は別のエージェントなので**文脈は分かれている** (作る途中の資料を見ない)．
       モデルを変えるのは，それに加えて癖の重なりを減らすため．
     - 選ばれたモデルと，オプションで指定されたか最初に聞いて決めたかを `review/triage.md` の冒頭に書く．
   - 検証役には `body.md`・`meta.yaml`・`report.txt` などを見せない (`review_prompt.md` で禁じてある)．
   - 論文が長いとき (目安 20 ページ超) は，範囲を分けて2〜3体に分担させてよい
     (同時に起動する数はユーザー設定の上限まで)．1体の中では順に確かめさせる．
3. 返ってきた結果を，作った側が1件ずつ判断する．
   - 採るもの: `body.md` か `meta.yaml` を直し，手順 3・4 をやり直す．
   - 採らないもの: 理由を書く (原文の誤りをそのまま写している，など．J-STAGE は PDF と HTML の内容が
     同一であることを求めるので，原文の誤りは直さない)．
   - 判断の記録を `W/review/triage.md` に残す (検証役の指摘の要約・採否・理由・直した所)．
   - 採否は事実で決める．指摘の文字が本当に PDF と違うかは，PDF の文字情報 (`page.search_for`) と
     ウェブ版 (`refs_web.txt`) で確かめる (37(1) では，見た目の空白やダッシュの字形の指摘2件が，
     PDF の文字情報どおりだったので採らなかった)．
4. A (内容の誤り・抜け) を直したときは，直した所だけをもう一度検証役に確かめさせる．

### 6. J-STAGE で確かめて登載する (人が行う)

**1本ずつ確かめるとき**: 下の 1〜3．**複数の論文をまとめて登載するとき**: 先に1本以上で 1〜2 を通してから，
`bundle.py` で1つの zip にまとめ，編集登載の「記事一括アップロード」へ上げる．

```
python $S/bundle.py W1 W2 W3 --out <出力先> [--kind update|new]
```

- `<資料コード>.zip` (中は `資料コード/巻/号/記事識別子/`) ができる．1つの zip には1つの資料だけ．
  各作業ディレクトリの `out/manifest.json` をもとに元のファイルから組む．
  **まとめた zip は登載が済んだら消してよい** (いつでも作り直せる．例の出力先は `jstage/work/_bundle/`)．
- 編集登載編「13. 記事アップロード」と別紙2 (2026-09-19 に確かめた):
  号のフォルダに複数の記事，巻のフォルダに複数の号を入れてよい．**複数の巻を入れてよいかは明記が無い**
  ので，`bundle.py` が警告を出す．最初は1巻ずつか少ない本数で試す．
- アップロード画面で選ぶ記事の種類は1回に1つ．**公開中の記事 (PDF だけで公開ずみのものなど) の更新は
  「本公開記事」**，新しく載せる記事は「通常公開」．両者は同じ zip に混ぜない (`--kind` は控え)．
- 巻・号は，アップロードの前に編集登載システムで作っておく．
- 画像の名前は `{記事識別子}_{連番}` の0埋めの通し番号 (`31_193_01.png`) で，`build.py` が付け，

## body.md の書式

| 書き方 | 意味 |
|---|---|
| `# 見出し` / `## 見出し` / `### 見出し` | 節 (`<sec>`) の入れ子 |
| 空行で区切った1行 | 段落 (`<p>`) |
| 空行なしで続く2行以上の `- ` / `1. ` | 箇条書き (`<list>`) |
| `*斜体*` `**太字**` `^上付き^` `~下付き~` | `<italic>` `<bold>` `<sup>` `<sub>` |
| `http(s)://...` | `<ext-link>` |
| `# 摘要` (設定の `sections.abstract`) | 和文の抄録 `<abstract>` (段落を保つ．本文からは外す) |
| `# 謝辞` / `# 引用文献` | `<ack>` / `<ref-list>` (引用文献は1件1行) |
| `<!-- ... -->` の行 | 読み飛ばす (メモ) |

図と表の枠:

```
:::fig F1 図1 fig1.png
畦畔の構造と名称．
:::

:::table T1 表1
表の題 (1行目)
<table> ... </table>       ← HTML (thead/tbody/tr/th/td，rowspan/colspan 可) か | 区切りの表
注の行 (表の後ろの行は table-wrap-foot)
:::

:::formula E1 (1)          ← 別行立ての式 (画像は formulas/eq1.png．番号は省ける)
:::
```

- 本文の「図1」「表1」「式(1)」は自動で `<xref>` になる．「著者 年」の引用も自動 (著者表記のかたまりが
  文献の著者名の先頭と一致し，年が同じもの)．「1991a, b」「2004, 2005」のような続きも扱う．
- 表のセルの中の引用もリンクする．
- 原文の表記揺れで自動では当たらない引用は，`{{著者名の先頭 年|表示の文字}}` と書くとその文献へリンクする
  (例: `{{北海道環境科学研究センター 2005|北海道環境科学センター（2005）}}`)．**表示の文字は原文のまま**にする
  (J-STAGE は PDF と HTML の内容が同一であることを求めている)．

## 他の雑誌に広げるとき

`journals/vegsci.yaml` を写して `journals/<資料コード>.yaml` を作り，次を合わせる．

- `layout`: 見出しの書体と記号・段落の字下げ・キャプションの形．
  **字の大きさ (本文・大見出し・文献) と柱・脚注の位置は PDF ごとに自動で決める** (`report.txt` の
  「組み方 (自動)」)．設定の値は自動で決められないときの既定値．
- `sections`: 摘要・謝辞・引用文献の見出しの文言．
- `article_types`: 原稿種別と J-STAGE の article-type の対応．
- 引用が番号式 (1) や上付き番号) の雑誌は，`build.py` の `link_citations` に別の規則が要る (未実装)．

## できないこと (いまの版)

- **数式は画像で載せる (`:::formula` → `<disp-formula><graphic/>`)．MathML は組まない**
  (2026-09-19 ユーザ指示で画像の道を選んだ)．画像なので検索・読み上げには乗らない．
  MathML が要るときは，全文 XML 作成ツールの画面で足すほうが早い．
- 電子付録・Graphical Abstract・ファンド情報は組まない．
- 本文の脚注 (`<fn>`) は扱わない．
- 引用文献の DOI (`<pub-id>`) は付けない (J-STAGE は付けると引用リンクが増えると勧めている)．
